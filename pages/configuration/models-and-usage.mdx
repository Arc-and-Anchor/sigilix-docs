# Models

Sigilix runs on the Sigilix model family. The product is Sigilix, the current default coding model is **Boreas**, and the upcoming family is **Boreas, Pyroeis, Astraeus, Phanes**.

The hosted PR review engine still runs specialist roles for logic, security, performance, and tests, then synthesizes one inline-first GitHub review. Model choice changes the depth and budget of the reasoning behind a surface; it does not bypass grounding, evidence, or the trust ledger.

<FeatureCards>
<FeatureCard title="Boreas · Light">
    Fast, grounded everyday coding. Boreas is tuned for the CLI, chat, and common review work where speed matters and repository context does most of the lift.
</FeatureCard>
<FeatureCard title="Pyroeis · Base">
    Balanced reasoning for larger edits, multi-file questions, and work that needs more deliberation than Boreas without moving to the deepest tier.
</FeatureCard>
<FeatureCard title="Astraeus · Premium">
    Deep reasoning for subtle logic, security, architecture, and blast-radius questions where extra depth is worth the additional usage cost.
</FeatureCard>
<FeatureCard title="Phanes · Frontier">
    Coming soon. Phanes is part of the Sigilix model family, but it is not available in the current portal usage model yet.
</FeatureCard>
</FeatureCards>

<Callout type="info">
Phanes is intentionally documented as **coming soon**. Do not treat it as selectable until it appears in the product and portal usage model.
</Callout>

## How the review engine uses models

The GitHub App review path is the authoritative code-review product. It installs as a GitHub App, reviews pull requests inline first, and uses the earned context layer before posting findings: repository index, dependency graph, review memory, learned rules, evidence manifests, and the trust ledger for verified findings.

The public role names in review output are stable: logic, security, performance, and tests feed the synthesizer. The exact model behind a role can change as Sigilix tunes the product, so these docs describe the model tiers rather than promising a fixed vendor model ID.

## How CLI and chat use models

The CLI binary is `sigilix`. Terminal sessions, chat, and local review workflows draw on the same grounded context as hosted reviews. Where a paid plan enables bring-your-own provider routing for CLI and chat, the model you bring still works against Sigilix's verified repository context rather than starting from an empty prompt.

Use the CLI to inspect what your account and build expose:

```bash
sigilix models
sigilix --help
```

## Usage lives on the canonical page

Model selection affects which usage pool and model row a request spends against, but the rules for pools, windows, caps, and upgrade behavior are centralized on [Usage & Limits](/usage-limits).

The verified usage model is:

- Per-seat usage covers coding-agent and chatbot activity.
- Organization usage covers PR reviews, Linear triage, and Slack usage.
- The short window is rolling 5 hours.
- The weekly window resets Monday at 9:00 AM local time.
- Usage is count-based by request/action, not per-minute metering.
