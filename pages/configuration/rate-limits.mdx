# Usage limits redirect

The rate-limit details for Sigilix now live on [Usage & Limits](/usage-limits). That page is the canonical source for pools, windows, reset timing, plan relationships, and what happens when a cap is reached.

<Callout type="info">
The old private-beta rate-limit copy described review-only windows and a five-day reset cadence. The current product uses two pools, a rolling 5-hour window, and a weekly window that resets Monday at 9:00 AM local time.
</Callout>

## Current model at a glance

- **Per-seat pool:** coding-agent and chatbot usage.
- **Organization pool:** PR reviews, Linear triage, and Slack usage.
- **Windows:** rolling 5-hour session window plus weekly limit.
- **Metering:** request/action counts, not per-minute time metering.
- **Caps:** when a pool reaches 100%, new requests in that window pause until reset; overage is not billed.
