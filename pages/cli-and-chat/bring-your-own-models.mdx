# Bring Your Own Key (CLI)

The Sigilix CLI runs on **Sigilix's own models by default** — no setup required. On paid tiers you can optionally **connect your own model-provider API key** and have the CLI agent run on your provider instead, paying that provider directly. Whatever model you bring still fetches Sigilix's verified [earned-context layer](/how-it-works/earned-context), so it inherits the grounding of a Sigilix review without re-deriving your repository.

<Callout type="info">
**Bring-your-own-key applies to the CLI only, and it's opt-in.** The CLI defaults to Sigilix's models; you connect a provider by choice. The [Deep-Research Chat](/cli-and-chat/deep-research) always runs on Sigilix models and cannot be pointed at another provider — it's the metered, grounded surface. The hosted PR ensemble also runs Sigilix's per-role tuned models.
</Callout>

This is the whole bet behind bring-your-own-key: the value isn't the model. The value is the **verified context the model fetches**. A frontier model with a generic prompt re-discovers your codebase every session and guesses at the edges. The same model pointed at Sigilix's earned context starts from a repo that has already been indexed, graphed, reviewed, and remembered.

## What you can connect

A **model-provider API key** is a key you already hold with a model provider — not another company's CLI. Connect one and the Sigilix CLI agent routes its model calls through it, billed to your account with that provider.

<FeatureCards>
<FeatureCard title="OpenAI">
    Connect your OpenAI API key. The CLI agent runs on OpenAI models; you pay OpenAI directly.
</FeatureCard>
<FeatureCard title="Anthropic">
    Connect your Anthropic API key. The CLI agent runs on Claude models; Anthropic bills your account.
</FeatureCard>
<FeatureCard title="OpenRouter">
    Connect an OpenRouter key to reach a broad range of models through a single provider account.
</FeatureCard>
</FeatureCards>

<Callout type="info">
This is a key you supply, not a separate tool you point Sigilix at. You are bringing a **provider API key** so the Sigilix CLI agent can run on that provider — the CLI is still Sigilix, still grounded, still gated.
</Callout>

## How it fits together

The model is the engine; the earned-context layer is the fuel. Bringing your own key swaps the engine without touching the fuel — and only on the CLI.

<Steps>

### Hosted reviews build the context

Every PR review deposits a verified layer — index, code graph, trust ledger, review memory, evidence manifests. This is the substrate the CLI agent fetches.

### You connect a provider (optional)

By default the CLI runs on Sigilix's models. To use your own, connect an OpenAI, Anthropic, or OpenRouter API key and select it as the active provider for the CLI.

### Your model fetches earned context

When you run a CLI review or agent session, Sigilix expands the request with the earned-context layer before handing it to your model — so it judges against the whole repo.

### You pay the provider, Sigilix supplies the rigor

Model billing lands on your provider account. The believability gates, context expansion, and proof-tier receipts come from Sigilix.

</Steps>

## Connecting a provider key

The CLI exposes model selection through `sigilix config`. By default no provider is connected and the CLI uses Sigilix's models; connecting a key is a deliberate opt-in.

```bash
# Inspect the active model — defaults to Sigilix's models
sigilix config model

# Connect your own provider key (stored via your env / secret manager)
sigilix config key set

# Route the CLI agent through your connected provider (illustrative)
sigilix config model openai
sigilix config model anthropic
sigilix config model openrouter

# Switch back to Sigilix's models at any time
sigilix config model sigilix
```

<Callout type="info">
Commands above are illustrative — the precise flags and provider names are surfaced by `sigilix config model` for your account during the beta. Authentication follows each provider's own flow; you supply the provider API key.
</Callout>

## Frequently asked

<details>
<summary>Can the Deep-Research Chat use my own model?</summary>

No. The Deep-Research Chat always runs on Sigilix's models — it's the metered, grounded surface and cannot be pointed at another provider. Bring-your-own-key applies to the **CLI only**.

</details>
  <details>
<summary>Does bringing my own key change the hosted PR review?</summary>

No. The hosted PR ensemble runs Sigilix's per-role tuned models behind cross-provider fallback so one outage can't silence a specialist. Bringing your own key applies only to the CLI. See [The Ensemble](/how-it-works/the-ensemble).

</details>
  <details>
<summary>Who pays for model usage?</summary>

When you connect your own key, model usage runs on your account with that provider, with no Sigilix model markup on those CLI runs. When you use Sigilix's models, usage draws from your per-seat pool — see [Usage &amp; Limits](/usage-and-limits).

</details>
  <details>
<summary>Does my model still get Sigilix's grounding?</summary>

Yes. The grounding doesn't come from a particular model — it comes from the earned-context layer and the believability gates. Whatever model you connect fetches that verified context, so it reasons about the whole repo without re-deriving it.

</details>
  <details>
<summary>What if I don't connect a key?</summary>

Then the CLI runs on Sigilix's models — the default. Bringing your own key is for teams that want to run the CLI agent on their own provider account.

</details>
