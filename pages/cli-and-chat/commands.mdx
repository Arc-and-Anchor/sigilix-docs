# CLI Command Reference

This page covers the **Sigilix CLI** — the `sigilix` binary you run in your terminal. For the `@sigilix` / `/sigilix` commands you type on a PR comment, see [Slash Commands](/configuration/commands); those run on the hosted GitHub App, while the commands here run locally and reach for the same [earned-context layer](/how-it-works/earned-context).

<Callout type="info">
The Sigilix CLI is part of the **private beta**. Availability is per-account — [join the private beta](https://app.sigilix.ai) or contact <a href="mailto:support@sigilix.ai">support@sigilix.ai</a> to get it enabled. The commands and flags below are **representative**; run `sigilix --help` and `sigilix <command> --help` to see exactly what your account exposes.
</Callout>

## Command overview

| Command | What it does |
|---|---|
| `sigilix` | Launches the grounded coding agent — reads, edits, and verifies code in your repo |
| `sigilix review` | Runs the five-specialist ensemble on local changes, behind the believability gates |
| `sigilix chat` | Opens Deep-Research Chat, grounded in your repo and review history |
| `sigilix mcp` | Connects MCP servers so the agent can reach your tools — see [MCP](/mcp) |
| `sigilix config` | Inspects and sets configuration — model selection, provider keys |
| `sigilix auth` | Authenticates the CLI to your Sigilix account |
| `sigilix --help` | Lists available commands and global flags |

## `sigilix review`

Runs Metis, Argus, Iris, and Eunomia in parallel — unified by Harmonia — against your local changes, after the deterministic checks and behind the same believability pipeline a PR review uses. By default it diffs your working tree against the merge-base with the default branch.

```bash
# Review the working tree against the default-branch merge-base
sigilix review

# Review a specific base or commit range
sigilix review --base origin/main
sigilix review --range HEAD~3..HEAD

# Narrow to a subtree (path filters from sigilix.json are also honored)
sigilix review --path "packages/api/**"
```

<details>
<summary>Representative flags</summary>

- `--base <ref>` — review the diff against this ref instead of the computed merge-base.
- `--range <a..b>` — review an explicit commit range.
- `--path <glob>` — scope the review to matching paths, on top of your `sigilix.json` filters.

These are illustrative — run `sigilix review --help` for the authoritative list on your account.

</details>
  <details>
<summary>Exit status</summary>

The command exits non-zero when a blocking finding survives the gates, so you can wire it into a pre-push hook or a CI step as a fast first pass ahead of the authoritative hosted PR review.

</details>
  <details>
<summary>What the output looks like</summary>

A Harmonia summary followed by inline findings tagged by specialist (Metis / Argus / Iris / Eunomia), severity (Critical / Warning / Info), and proof tier (VERIFIED / GROUNDED / MODEL). See [Sigilix CLI](/cli-and-chat/cli) for a worked example.

</details>

## `sigilix chat`

Opens [Deep-Research Chat](/cli-and-chat/deep-research) — plain-language Q&A grounded in the index, code graph, trust ledger, and review memory. Ask why a finding fired, what a change affects, or how a subsystem fits together; answers anchor to retrieved evidence rather than guesses.

```bash
# Start an interactive chat session
sigilix chat

# Ask a single question and exit (illustrative)
sigilix chat "why did Argus flag the session compare on the last review?"
```

<details>
<summary>What it can retrieve</summary>

Past findings, the specialist that raised them, the code they cited, their proof-tier receipts, and the rules you've taught — all from the earned-context layer. The chat reasons over these anchors instead of improvising.

</details>
  <details>
<summary>Grounded by design</summary>

When the earned-context layer doesn't contain what a question needs, the chat says so rather than fabricating — the same believability bar as a review.

</details>

## `sigilix mcp`

Connects [MCP](/mcp) servers to the CLI so the grounded coding agent can reach your tools — GitHub, Linear, Sentry, Cloudflare, Supabase, Notion, Atlassian, Stripe, Vercel, and more. Catalog servers connect by name with OAuth auto-detection; custom servers connect by URL.

```bash
# Interactively pick from the catalog or add a custom server
sigilix mcp add

# Add a known catalog server by name (configures the endpoint + OAuth)
sigilix mcp add linear

# Add a custom remote server by URL
sigilix mcp add my-server --url https://mcp.example.com/mcp

# List connected servers and their auth status
sigilix mcp list

# Review or revoke stored OAuth credentials
sigilix mcp auth list
```

See [MCP](/mcp) for the full catalog and the portal connection flow.

## `sigilix config`

Inspects and updates CLI configuration. The most common use is selecting the model behind your terminal workflow — on paid tiers you can bring your own (Codex CLI, Claude Code, or your own SDK/keys). See [Bring Your Own Models](/cli-and-chat/bring-your-own-models).

```bash
# Inspect the active model and available providers
sigilix config model

# Select a provider (illustrative)
sigilix config model codex
sigilix config model claude-code
sigilix config model custom

# Manage a bring-your-own provider key (store via your env/secret manager)
sigilix config key set
```

<Callout type="info">
Model and provider names are surfaced by `sigilix config model` for your account. Authentication follows each provider's own flow — Codex CLI and Claude Code authenticate to OpenAI and Anthropic; "your own SDK / keys" uses the provider credentials you supply.
</Callout>

## `sigilix auth`

Authenticates the CLI to your Sigilix account so it can reach the earned-context layer for your repositories. Run this once after install.

```bash
# Authenticate the CLI to your Sigilix account
sigilix auth login

# Check who you're authenticated as
sigilix auth status

# Sign out
sigilix auth logout
```

<Callout type="info">
Provider authentication (for the model you bring) is separate from Sigilix account authentication — `sigilix auth` connects you to Sigilix; provider credentials are managed via `sigilix config`. See [Bring Your Own Models](/cli-and-chat/bring-your-own-models).
</Callout>
