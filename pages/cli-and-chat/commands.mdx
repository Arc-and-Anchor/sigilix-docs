# CLI Command Reference

The CLI binary is **`sigilix`**. Some internal package paths are inherited from the fork this repo began as, but the product, binary, and docs surface are Sigilix.

For commands typed in a GitHub PR comment, see [Slash Commands](/configuration/commands). Those run through the hosted GitHub App. The commands here run locally and connect to the same grounded repository context where your account has access.

<Callout type="info">
The CLI is still account-gated during beta. Use `sigilix --help` and `sigilix <command> --help` as the authoritative command list for your installed build.
</Callout>

## Command overview

| Command | What it does |
|---|---|
| `sigilix` / `sigilix run` | Starts an interactive terminal agent or sends one prompt. |
| `sigilix chat` | Opens the chat surface where enabled by your account/build. |
| `sigilix review` | Runs review from the terminal against local changes, a diff, or a GitHub PR where enabled. |
| `sigilix mcp` | Manages Model Context Protocol servers. |
| `sigilix models` | Lists available providers and models for the installed build. |
| `sigilix account` / `sigilix auth` | Authenticates or inspects account state, depending on your build. |
| `sigilix --help` | Lists the exact commands and flags installed locally. |

## Chat and terminal agent

Start Sigilix in the repository you want it to understand:

```bash
# Open an interactive terminal session
sigilix

# Equivalent explicit form in current CLI builds
sigilix run

# Send a one-shot prompt where supported
sigilix run "explain the session recovery code path"
```

Inside the interactive session, slash commands expose the installed command, MCP, agent, model, and skill surfaces. Common controls include:

```text
/model
/mcp
/mcps
/agents
/skills
/help
```

Skills are loaded through the interactive skill menu and skill tool. The CLI source exposes skills there; it does not currently expose a separate top-level `sigilix skills` yargs command.

## Review

The review surface brings Sigilix's code-review engine into the terminal. Hosted PR review through the GitHub App remains the authoritative review path, but local review lets you catch issues before opening or updating a PR.

```bash
# Review uncommitted local changes
sigilix review --uncommitted

# Review against a base branch
sigilix review --diff main

# Review a GitHub PR by owner/repo and PR number
sigilix review --repo owner/repo --pr 128
```

Review output follows the same product contract as hosted reviews: one synthesized result, inline findings where possible, severity, and proof/evidence context. The exact flags depend on the CLI build available to your account; run `sigilix review --help` for the installed contract.

## MCP

Use `sigilix mcp` to connect and inspect MCP servers:

```bash
sigilix mcp list
sigilix mcp add <name>
sigilix mcp auth <name>
sigilix mcp logout <name>
sigilix mcp debug <name>
```

Configured MCP servers can add issue, CI, observability, docs, database, and other app context to chat and agent work. See [MCP Catalog](/mcp/overview) for the catalog orientation.

## Models

Use `sigilix models` to inspect the model providers and models visible to your installed build:

```bash
sigilix models
sigilix models sigilix
sigilix models --verbose
```

For product-tier positioning, see [Models](/configuration/models-and-usage). Boreas is the light/fast everyday model, Pyroeis is base/balanced, Astraeus is premium/deep reasoning, and Phanes is frontier/coming soon.

## Account and authentication

Current builds expose account/authentication commands for connecting the CLI to your Sigilix account and the earned-context layer. Use your local help output for the precise spelling on your build:

```bash
sigilix account --help
sigilix auth --help
```

Provider authentication for bring-your-own CLI/chat models is separate from Sigilix account authentication.
