# CLI & Chat

<Callout type="info">
The Sigilix CLI and Deep-Research Chat are part of the **private beta**. Availability is per-account during the beta — [join the private beta](https://sigilix.ai) to get access, and contact <a href="mailto:support@sigilix.ai">support@sigilix.ai</a> if you are already in and want it enabled.
</Callout>

The hosted GitHub App reviews every PR. But review is not the only place the depth pays off — and the PR thread is not the only place developers work. The Sigilix CLI brings the same review to your terminal, and Deep-Research Chat lets you interrogate the repository and its review history in plain language.

Both draw on the [earned-context layer](/how-it-works/earned-context): the index, code graph, trust ledger, review memory, and evidence manifests that every review deposits. The terminal and the chat read from that understanding instead of rebuilding it.

## Two surfaces, one understanding

<FeatureCards>
<FeatureCard title="Sigilix CLI">
    Review parity in the terminal. Run a Sigilix review on local changes before you open a PR — the same five-specialist ensemble and believability gates, reaching for the same earned context the hosted reviews built.
</FeatureCard>
<FeatureCard title="Deep-Research Chat">
    A chat grounded in your repo and its review history. Ask why a finding fired, what a change affects, or how a subsystem fits together — answers are anchored in the index, code graph, and past reviews, not guessed.
</FeatureCard>
</FeatureCards>

## Grounded in earned context

The difference between the Deep-Research Chat and a generic code chatbot is the substrate. A generic chatbot reads whatever fits in its window. Deep-Research Chat reads from the earned-context layer:

<FeatureCards>
<FeatureCard title="The repo, in context">
    The code graph and index mean answers reason about callers, dependencies, and symbols across the whole repository — the same context-before-judgment that powers reviews.
</FeatureCard>
<FeatureCard title="The review history">
    Past findings, their proof-tier receipts, and taught rules are retrievable. The chat can tell you not just what the code does, but what Sigilix has already learned about it.
</FeatureCard>
</FeatureCards>

## Tools and skills

The Sigilix CLI is more than a reviewer — running `sigilix` launches a **grounded coding agent** that reads, edits, and verifies code in your repo. Two things extend what it can do:

<FeatureCards>
<FeatureCard title="MCP servers">
    Connect your tools over the Model Context Protocol — GitHub, Linear, Sentry, Cloudflare, Supabase, Notion, Atlassian, Stripe, Vercel, and more — with `sigilix mcp add`. The agent then reaches those tools on your behalf. See [MCP](/mcp).
</FeatureCard>
<FeatureCard title="Skill library">
    The CLI ships a library of 23 bundled skills — focused, reusable procedures the agent loads on demand (code review, TDD, systematic debugging, conventional commits, frontend design, MCP building, and more) — so it follows proven playbooks instead of improvising.
</FeatureCard>
</FeatureCards>

## Bring your own key (CLI only)

The CLI runs on Sigilix's own models by default. On paid tiers you can optionally connect **your own model-provider API key** so the CLI agent runs on your provider instead, billed directly to you:

<FeatureCards>
<FeatureCard title="OpenAI">
    Connect your OpenAI API key; the CLI agent runs on OpenAI models, and you pay OpenAI directly.
</FeatureCard>
<FeatureCard title="Anthropic">
    Connect your Anthropic API key; the CLI agent runs on Claude models on your own account.
</FeatureCard>
<FeatureCard title="OpenRouter">
    Connect an OpenRouter key to reach a broad range of models through one provider account.
</FeatureCard>
</FeatureCards>

<Callout type="info">
Bring-your-own-key is **opt-in and CLI-only**. The [Deep-Research Chat](/cli-and-chat/deep-research) always runs on Sigilix's models and can't be pointed at another provider, and the hosted PR ensemble runs Sigilix's per-role tuned models. Whatever model you connect on the CLI still fetches the earned-context layer. See [Bring Your Own Key](/cli-and-chat/bring-your-own-models).
</Callout>

## How it fits together

<Steps>

### Reviews build the context

Every hosted review deposits a verified layer — index, code graph, trust ledger, review memory, evidence manifests.

### The CLI reviews locally

Run a review from the terminal before opening a PR, reaching for the same earned context — on Sigilix's models, or your own connected provider key.

### The chat answers from history

Ask the Deep-Research Chat about the repo or a past finding; it answers grounded in that same layer.

</Steps>
